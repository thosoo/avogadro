## Completion summary

Outcome: The modern rendering tier now gets its camera projection/modelview from the Camera's CPU-authored matrices instead of the (dead on Core) GL matrix stack, so molecules render correctly on Core-only drivers.

Changed: Camera::applyProjection() authors d->projection CPU-side (perspective/orthographic formulas, no GL stack calls) with a projection() accessor; paintGL, the GL_SELECT pick path, and paintGL2 upload the authored matrix via glMultMatrixd; currentModelViewProjection()/currentModelView() read the Camera matrices; the Core diagnostic was narrowed; and testCameraProjectionMatchesGLU was added (closed-form 1e-12 + float-rounded live probe at 1e-6) with Core-profile QSKIP guards on the three fixed-function tests.

Evidence: OpenSpec state all_done (9/9 tasks, 0 remaining); GLLA mirror 9/9 complete; fresh-context reviewer OK-with-notes (no code defect); oracle verified the fix on a real GL 4.5 Compatibility context (float-rounded residual exactly 0, confirming the authored matrix matches the stack).

Tests: cmake build (avogadro + modernrenderertest) success; ctest full suite 40/40 pass; modernrenderertest on real GL (xvfb) 20/20 pass with 3 honest Core skips; on the target Core-only GT200 box (10.66.0.12) 20/20 pass + 3 skips and the app resolves Core Profile and selects the modern tier with the authored-matrix diagnostic.
