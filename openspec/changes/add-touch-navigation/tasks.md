## 2. Gesture semantics

- [x] 2.1 Implement PENDING → STROKE: travel ≥ slop (named constant, ~10 logical px) synthesizes press at current position then moves; implement tap: release < slop and quick synthesizes press+release pair; jitter below slop emits nothing. — Verify: `testJitterBelowSlopEmitsNothingThenStroke`, `testTapSynthesizesClick`, `testStrokeSynthesizesPressMoveRelease`.
- [x] 2.2 Implement GESTURE: entered when a second point is observed while PENDING *or* a `TouchBegin` carries ≥2 points (straight to GESTURE, no pending state, no synthesized tool events); distance delta between the two tracked point ids drives `Navigate::zoom` with the wheel sign convention (fingers apart = zoom in); centroid delta drives `Navigate::translate` pan; the gesture ends when either original point id lifts, leaving the camera at its final pose; neither gesture's zoom nor pan reaches any tool. — Verify: `testBothFingersBeginGoesStraightToGesture`, `testPinchSpreadZoomsInAndSqueezeZoomsOut`, `testTwoFingerPanMovesCentroid`, `testGestureEndHoldsCamera`, `testSecondPointDuringPendingBecomesGesture`.
- [x] 2.3 Implement the second-class rule: any point arriving during PENDING/STROKE/GESTURE is blacklisted until it lifts; the blacklist survives stroke end (a resting finger that lifts after a stroke never becomes a fresh touch); a third finger never substitutes into a broken pinch pair; STROKE completion on finger-1's release still synthesizes the release normally while finger-2 stays blacklisted. — Verify: `testPalmMidStrokeIsBlacklisted`, `testRestingFingerNeverWakes`, `testThirdFingerDoesNotSubstituteIntoPinch`.
- [x] 2.4 Preserve one-finger rotate: a synthesized press the active tool ignores falls through to `m_navigateTool` exactly as a real mouse press does. — Verify: `testOneFingerRotateWithNavigateTool`.
