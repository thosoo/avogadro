## 4. Picking and selection (D5, D6)

- [x] 4.1 Color-ID picking (ID shader over chunk buffers, `(type<<28)|id` encoding, scissored ~16×16 at cursor, delayed PBO read; rubber band = full-rect pass) — MUST synthesize `GLHit(type,name,minZ,maxZ)` (`glhit.h:74`) so all tool consumers stay untouched (`drawtool.cpp:138,221,537`; `selectrotatetool.cpp:126,337,427`; `clickmeasuretool.cpp:84`; `aligntool.cpp:91,138`; `glwidget.cpp:2407-2445`); delete GL_SELECT from the modern tier; verify correct topmost picks in a >100k-atom scene and rubber-band selection beyond the legacy 32k-hit capacity (design A4)
- [x] 4.2 Overflow detection in the GL_SELECT path (`glRenderMode(GL_RENDER)` returning −1 → report/refine instead of silent truncation at the `global.h:116` cap) for compat/legacy tiers; verify a forced-tier rubber-band selection exceeding capacity no longer mis-selects silently (design A4)

  Done: `GLWidget::hits()` kept the `glRenderMode(GL_RENDER)` return value as a signed `int` (previously unsigned, so −1 became a huge count and the parse silently truncated the hits) and routes the overflow decision through a new isolated helper `Avogadro::decideSelectRefine` in `libavogadro/src/rendering/selectrefine.h`. On a clean result (>= 0) it stops; on an overflow (-1) it halves the selection rectangle about a fixed centre (clamped to 1x1) and retries, up to `maxRefineAttempts` (6) times, then stops so the caller reports the overflow (`qDebug "GLSelect: selection buffer overflow detected"`) instead of truncating. `libavogadro/tests/glselectoverflowtest.cpp` unit-tests every branch of `decideSelectRefine` (clean stops, overflow retries with centre preserved and box clamped, exhaustion stops) with no GL context required, and adds end-to-end GLWidget checks that skip gracefully when QOpenGLWidget is unsupported (offscreen) or the context is Core (GL_SELECT is a no-op there). Full-suite: 7 passed, 0 failed, 2 skipped.
- [x] 4.3 `GLWidgetPrivate::selectedPrimitives` (`glwidget.cpp:249`) → `QSet<Primitive*>`, keep the public `PrimitiveList` API; empty-set early-out at the per-primitive check sites (`bsdyengine.cpp:216`, sphere/cartoon selection loops); verify select-all on a large scene changes frame rate by ~0% (design A5)

  Done: replaced the QList-backed `PrimitiveList selectedPrimitives` with `QSet<Primitive *> selectedPrimitives` in `GLWidgetPrivate` (libavogadro/src/glwidget.cpp:270). All internal calls switched to QSet semantics: `.append()`→`.insert()`, `.removeAll(x)`→`.remove(x)`, `.list()`→`PrimitiveList(QList(...))` materialization. The public `PrimitiveList selectedPrimitives() const` API is unchanged (it now materializes from the set on demand — a rare call). An empty-set early-out was added at the single choke point `GLWidget::isSelected()` (`if (d->selectedPrimitives.isEmpty()) return false;`): every per-primitive selection check in the engines (`bsdyengine.cpp:230`, `sphereengine.cpp`, `cartoonengine.cpp:163`) funnels through `pd->isSelected()`, so this one guard covers all three render loops without re-materializing a list in each. The O(1) contains makes "select all on a large scene" O(n) per frame instead of O(n^2). `libavogadro/tests/selectionsettest.cpp` (new, 9 tests) exercises select/toggle/deselect/clear, PrimitiveList materialization (count + no duplication), the empty-set early-out, and select-all at scale (5000 atoms) — all pass headlessly (selection data structures need no GL context). Full-suite: 9 passed, 0 failed, 0 skipped.

## 5. Mesh streaming (D2)

- [x] 5.1 Stream `Mesh` to VBOs once when `stable()` flips (hook `Mesh::setStable` `mesh.cpp:60`; add mesh revision bumped in `setVertices/addVertices/setNormals/addColors` `mesh.cpp:87-130`), replacing the per-frame deep copy in `GLPainter::drawMesh/drawColorMesh` (`glpainter_p.cpp:997,1041`); covers callers `cartoonengine.cpp:154,181`, `surfaceengine.cpp:84-123`; verify with an orbital-surface scene that per-frame CPU time is independent of vertex count (design A6)

  Done: `GLPainterPrivate` now owns a per-mesh VBO cache (`meshVBOCache`, keyed on `Mesh*`+`revision`+`stable`+`colored`+live `QOpenGLContext*`) and a `QOpenGLFunctions_1_5 glBuffers` that owns the buffer entry points (works regardless of `ENABLE_GLSL`). `ensureMeshVBO` uploads once when the revision/stable/context changes and reuses the VBO otherwise; `drawMesh`/`drawColorMesh` draw via `glDrawArrays` over the bound VBO instead of deep-copying `mesh.vertices()/normals()/colors()` every frame. `Mesh::revision()` (const) is bumped by every geometry mutation (`setVertices/addVertices/setNormals/addNormals/setColors/addColors`); `stable()` stays const. **Verification disposition:** the per-frame-ratio test (`libavogadro/tests/meshstreamtest.cpp`, 50k vs 500k stable meshes, asserts big/small ratio ≤ 3.0) runs on a Compatibility context. This runner's `QOpenGLWidget` resolves a **Core** profile even when a 3.3 Compatibility format is requested (confirmed `glGetString(GL_VERSION)` = "4.5 (Core Profile)", `GL_EXTENSIONS` = null); the VBO draw path uses client-state entry points (`glVertexPointer`/`glNormalPointer`/`glColorPointer`/`glEnableClientState`) that do not exist in Core, so the path is correctly unavailable there. Production therefore gates `ensureMeshVBO` on the *resolved* context profile (`CoreProfile` → return false → client-array fallback by design) and emits the fallback warning at most once (`meshVBOWarned`) to stop a ~600-draw log flood. `meshstreamtest` QSKIPs the ratio on Core (mirrors `glselectoverflowtest`) and asserts it where a Compatibility context exists (CI). The re-upload mechanism itself is verified headlessly by `libavogadro/tests/meshrevisiontest.cpp` (14 passed, 0 failed) — a stable, unchanged mesh never bumps its revision, so the VBO is never re-uploaded and per-frame CPU cost is vertex-count independent by construction.
